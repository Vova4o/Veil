## 1. Решения пользователя

- **Одна модель:** `moodyKrea2Mix_v40.safetensors` (Moody Krea 2 Mix V4.0 FP8). Другие Krea2-чекпоинты (redcraft, lustify) требуют других графов и компонентов — вне рамок.
- **Три подготовленных режима**, никаких построителей графов и пользовательских флоу:
  1. **По референсу** (`reference`): фото + необязательные пожелания → агент пишет подробный промпт по референсу → txt2img.
  2. **Правка фото** (`edit`): фото + что изменить → агент пишет команду правки → граф Krea2 Identity Edit (LoRA + ноды `comfyui-krea2edit`).
  3. **По описанию** (`text`): только текст → агент пишет промпт → txt2img.
- **В UI нет выбора модели.** Все остальные модели (`model_01…08` и любые другие профили) из Create убираются; единственная модель — Moody Krea2. Пользователь переключает только **режимы**.
- **Пользователь выбирает только** режим, соотношение сторон и количество изображений **1–4**. Все разрешения около **1 МП**. Никакого выбора моделей, LoRA, качества.
- **UI не изобретаем заново, а адаптируем текущий Create**; когда есть фото, слева показываем карточку «До», справа результаты «После» — для сравнения.
- **Агенты:** Direct (OpenAI-compatible), OpenCode, **Claude Code**, **Antigravity (`agy`)** и **Codex** (2026-10-11). Агент берётся из умолчаний вкладки Integrations.
- **OpenCode — агент по умолчанию** (решение 2026-10-11): его бесплатные модели Zen работают сразу после установки, без подписки и ключей. Поддерживаются и npm CLI, и десктоп-приложение; список моделей с выбором и запоминанием; мультимодальность определяется только для OpenCode (Codex / agy / Claude Code всегда считаются мультимодальными). Для роли Vision в списке только модели, которые видят картинки; текстовые роли принимают любую модель.
- **Ноды** ставятся автоматически по кнопке «Скачать недостающее» (архив закреплённого коммита), плюс инструкция для ручной установки.
- **Кнопка «Улучшить детали»** на готовом кадре — да; недостающее скачивать самостоятельно.
- **Режим 2 с NSFW** пользователь проверял — работает; запасных маршрутов сейчас не делаем.
- **Инструкция агента:** на основе `instruction.md` пользователя (решение 2026-10-11, вечер), разложена на модули и адаптирована под Qwen3-VL; правила про неотению и детские пропорции удалены полностью, добавлено жёсткое правило «интим — только явно взрослые» (7.1); потом перенос на скиллы.

## 4. Рецепты графов

Профиль: [`app/comfyui/simple_models/krea2_moody_v40/`](../app/comfyui/simple_models/krea2_moody_v40/).

### 4.1 txt2img (`workflow.json`, режимы `text` и `reference`)

- `UNETLoader` → `CLIPLoader (krea2)` → `CLIPTextEncode`; негатив — `ConditioningZeroOut`; латент `EmptySD3LatentImage`.
- Сэмплер **`dpmpp_2m_sde_gpu` + `sgm_uniform`, 8 шагов, CFG 1**.
- **SDA gate = 2:** `KSamplerAdvanced` шаги 0–2 на модели с LoRA SDA (`return_with_leftover_noise`), затем шаги 2–8 на базовой модели (`add_noise=disable`). Сила LoRA задаётся по режиму: `text` → 1.0, `reference` → 0.0 (композиция референса важнее разнообразия). При силе 0 ComfyUI пропускает LoRA, разбиение на два сэмплера сохраняет качество (проверено).
- Пакет 1–4 = **отдельные задачи в очереди** с сидами s, s+1…; картинки приходят по одной, на 8 ГБ это надёжнее латентного batch.
- Размеры: 1:1 → 1024×1024, 3:4 → 896×1152, 4:3 → 1152×896, 9:16 → 768×1344, 16:9 → 1344×768; `source` — пропорции фото при ~1 МП, шаг 32, ограничение 1:2.5…2.5:1 (`resolve_dimensions`).

### 4.1a Вариация (`variation.workflow.json`, режим `variation`, 2026-10-13)

Граф пользователя `moodyKrea2Mix_v40_auto_1MP_img2img.json` без пустого стека LoRA rgthree и без апскейла (он был в bypass): `LoadImage` → `ImageScaleToTotalPixels` (lanczos, 1 МП, `resolution_steps=16`) → `VAEEncode` → `KSampler` (8 шагов, CFG 1, `euler` + `simple`, **denoise**) → `VAEDecode` → `SaveImage` `CMV/Create/krea2_variation`; негатив — `ConditioningZeroOut`, без SDA.

- Это не дипфейк-режим: агент пишет то же точное описание фото, что в `reference` (та же инструкция, отдельного навыка нет), а генератор вдобавок получает само фото как стартовую картинку.
- **Шум выбирает только пользователь** ползунком 0–1 (шаг 0,05, по умолчанию 0,65); агенту он не передаётся. Зоны с подсказкой: до 0,35 — синяя, уклон к референсу, его артефакты переходят в результат; 0,35–0,55 — артефакты ещё могут перейти, но в основном перерисованы; 0,60–0,75 — оптимум: новая картинка без мелких артефактов; 0,80–0,95 — сходства мало; 1,0 — фото не участвует (остаются только пропорции).
- Размер — как у ноды: ~1 МП в пропорциях фото, кратно 16 (`variation_dimensions`); выбор пропорций в этом режиме скрыт.

### 4.2 Правка (`edit.workflow.json`, режим `edit`)

- `LoadImage` → `ImageScaleToTotalPixels` (1 МП, `resolution_steps=32`) → `VAEEncode`.
- `LoraLoaderModelOnly` identity edit r64 (1.0) → `Krea2EditModelPatch` (`ref_boost=4`, `ref_boost_a=1`, `fit_mode=fit`, `source_latent`, `source_image`, `target_latent`, `vae`).
- `Krea2EditGroundedEncode` позитив = команда правки, негатив = пустая команда с тем же фото, `grounding_px=768`.
- `KSampler` 8 шагов, CFG 1, `dpmpp_2m_sde_gpu` / `sgm_uniform` (калибровка 5.1), denoise 1 на новом `EmptySD3LatentImage` (исходник — не стартовый латент, а отдельное условие).
- Рецепт взят из проверенного прогона `image_gen` (`research/local-runs/workflows/moodykrea2-local-identity-edit.api.json`) и откалиброван живьём 2026-10-11 (5.1).
- Исходник загружается в ComfyUI через `ComfyUIClient.upload_image` (`input/cmv/cmv_source_<uuid>.png`).
- **Профили правки** (2026-10-11) — список `edit_profiles` в `manifest.json`; каждый задаёт все пять ручек графа (`cfg`, `steps`, `ref_boost`, `ref_boost_a`, `grounding_px`), они — привязки `edit.bindings.json` (`grounding_px` — у обоих `Krea2EditGroundedEncode`, негатив тогда работает как trained unconditional из README нод). Без явного профиля берётся первый для данного числа фото: `light` для одного, `donor` для двух.

  | id | Для чего | cfg | шаги | rb | rb_a | grounding | ~с/кадр |

  | `light` | смена одежды, бельё, причёска, мимика, стиль, частичное обнажение (5.3) | 1 | 8 | 4 | 1 | 768 | 115 |

  Профиль, сделанный для другого числа фото, — ошибка `edit_profile_invalid`. Привязка `negative_prompt` ведёт в негативный grounded-энкодер (та же картинка); текст там действует только при cfg > 1.
- **Второй референс** (донор: человек, тату, одежда) — фрагмент `edit.subject.workflow.json`: `LoadImage` → тот же `ImageScaleToTotalPixels` → `VAEEncode`; связи `subject_links` из `edit.bindings.json` ведут его в `Krea2EditModelPatch.source_latent_b` + `source_image_b` и в `image_b` обоих `Krea2EditGroundedEncode`. Порядок фиксирован: сцена — основные входы, донор — `_b`. По тултипу ноды `ref_boost` действует на **последний** референс (донор, ≤ 2), `ref_boost_a` — на первый (сцена, 1–4). Так же собран эталонный граф авторов нод (`workflows/krea2_identity_edit.json`, группа 2). У ноды есть ещё `ref_boost_mask` — усиление только по области референса (например, лицо донора), не тестировалось.
- `POST /api/simple/generate` в режиме `edit` принимает `edit_profile` и `subject_image` (data URL; загружается как `input/cmv/cmv_subject_<uuid>.png`), отвечает `edit_profile` и `seconds_per_image`; профиль пишется в черновик и в `extra_pnginfo` (`cmv_edit_profile`). В других режимах эти поля — ошибка `edit_only`. `/api/simple/models` отдаёт `edit_profiles` (id, подпись, описание, число фото, время).
- Авторский граф нод: `euler` / `simple`, 10 шагов, CFG 1, ref_boost 4. Их CHANGELOG предупреждает, что SDE-сэмплеры мешают каналу копирования референса при outpaint; на наших 16:9 / 1:1 (5.1) расширение вышло связным, но для смены пропорций держать `euler` запасным вариантом (этап 1c).

### 7.2 Технические требования к инструкции под Qwen3-VL

Как ComfyUI 0.39.1 кодирует текст для Krea2 (`comfy/text_encoders/krea2.py`, `qwen3vl.py`):

- Энкодер — **Qwen3-VL-4B** (LLM), модель получает скрытые состояния **12 слоёв** (2, 5, …, 35) через адаптер `txtfusion` в DiT — это не T5 и не CLIP.
- Промпт оборачивается в шаблон Qwen-Image: системная фраза *«Describe the image by detailing the color, shape, size, texture, quantity, text, spatial relationships of the objects and background»*, затем `user: {промпт}`, режим no-think. Префикс из условия вырезается, но токены промпта уже «прочитаны» в контексте этой фразы: энкодер настроен на **плотное описание кадра**.
- **Лимита длины нет** (`max_length=99999999`, без паддинга и нарезки на чанки, как у CLIP 77). Длина ограничена только размыванием внимания.
- Qwen3-VL **многоязычный** (китайский — родной; автор Moody пишет примеры промптов по-китайски, но его скилл выдаёт английский).
- В режиме правки `Krea2EditGroundedEncode` кодирует команду **вместе с картинкой** (image-grounded): команда может ссылаться на видимые объекты («платье слева»); у ноды есть пустой по умолчанию вход `system_prompt` — кандидат для эксперимента.

Требования к новой инструкции:

1. **Размещение:** новая инструкция — контент промпт-компилятора (`app/ai/prompting/content/…`, слой Krea2 + операции `reference` / `text` / `edit`) на этапе 2; разбивка на скиллы — этап 5. Корневой `instruction.md` удалить.
2. **Сериализация:** без T5-XXL и без правила «самодостаточный базовый блок в первых 500 токенах»; бюджет пересчитать от реальной длины, а не от лимита T5. Кандидат — раскладка по персонажам автора Moody (A/B из 7.3).
3. **Словарь под системный шаблон энкодера:** явно проговаривать цвет, форму, размер, фактуру, **количество**, видимый **текст** и **пространственные связи** (лево/право, передний/задний план, кто кого касается) — то, что шаблон просит описать.
4. **Без отрицаний и тегов:** «no X» по-прежнему может протечь в условие; описывать желаемую альтернативу. Весовой синтаксис `(word:1.2)`, теги качества и Pony/SDXL-токены — запрещены, как и сейчас.
5. **Язык:** по умолчанию английский; китайский как вариант — только по результатам A/B.
6. **Правка:** команда опирается на то, что энкодер видит фото — называть объекты так, как они видны, плюс явные цели сохранения (7.3); эксперимент с `system_prompt` у `Krea2EditGroundedEncode`.
7. Всё перечисленное проверять генерациями на одних и тех же сидах/референсах, а не принимать на веру.

### 7.3 Надстройки по режимам (этап 2)

- `reference`: базовая инструкция Krea2; текст пользователя — запрошенная трансформация.
- `text`: Scene Map строится по описанию; правило «не выдумывать отсутствующего на фото» заменяется на «заполнять недостающее согласованными творческими решениями»; паспорт и series lock — по истории сессии.
- `edit`: формат **команды правки** (editor instruction): что меняется + явные цели сохранения (Phase 2A: радужка, волосы, макияж, ногти, аксессуары; Phase 3: материал/крой; палитра/экспозиция/фон), без «keep pose» при смене позы; без полного описания сцены. Образцы — `image_gen/skills/forma-muse/references/editing-prompts.md`.
- **A/B на одних референсах:** (а) базовая раскладка новой инструкции, (б) она же с раскладкой абзацев по персонажам от автора Moody. Выбирает пользователь по картинкам.

## 12. Разделение способов правки и выбор профиля (2026-10-13)

Уточнённая схема пользователя: `From photo` остаётся txt2img по описанию агента. - Убраны обещания неизменности лица/сцены и точного копирования деталей из UI и описаний профилей. Попиксельное сохранение не обещается.

## 15. Antigravity: проверенный JSON вместо текстового ответа (2026-10-13)

На пользовательском скриншоте JSON ответа agy попал в журнал агента под `Queued`:
старый reader принимал каждую строку stdout за прогресс. Это само по себе не
подтверждало ошибку разбора. Отдельно обнаружено, что текстовый ответ agy может
содержать Markdown, несколько JSON-фрагментов, числовую `schema_version` и
служебные `toolAction` / `toolSummary`; удаление Markdown-ограждения этого не решает.

Адаптер теперь запускает agy с `--output-format json --json-schema cmv-result.schema.json`.
Схема строится из `PromptResult`, требует все пять полей и запрещает дополнительные.
Читается только `structured_output` из конверта со статусом `SUCCESS`, затем результат
проходит обычную Pydantic-валидацию. Поле `response` остаётся диагностическим журналом
хоста и не используется как промпт. Ненулевой exit code, отсутствие проверенного
результата и нарушение контракта завершаются ошибкой; повреждённый JSON не восстанавливается.

Финальный JSON больше не показывается строками прогресса. Ошибки агента получают
`stage: agent`: UI отделяет их от ошибок очереди ComfyUI, показывает техническую
диагностику в закрытых `Details` и возвращает кнопку Create в рабочее состояние.

`simple_models/krea2_moody_v40/prompt_style.md` и его неиспользуемое поле/загрузчик
удалены. Create уже собирал инструкции только из `app/ai/prompting/content/create/krea2/`.
В удалённом файле Pony/SDXL упоминались как запрет на их теги; энкодером был указан
Qwen3-VL. Файл не мог менять пакет инструкций Create.

Проверка: 829 pytest + 92 subtests, 69 Node-тестов, Ruff, Pyrefly по app, ESLint,
контракты OpenAPI и git diff --check. Browser smoke в Edge подтвердил выход из
ожидания при ошибке агента, доступную кнопку Create, диагностику в Details и
отсутствие постановки генерации в очередь. Живой запуск обновлённого адаптера:
Antigravity Gemini 3.8 Flash Low, нейтральная тестовая фотография сада,
29,6 с; все поля `PromptResult` валидны. Проверена доставка задания, чтение фото
и структурированный ответ агента; новая генерация изображения для этой правки не запускалась.
